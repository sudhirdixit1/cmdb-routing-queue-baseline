
\section*{Data availability}

All data are public, and every admitted event log is cited by its DOI: BPI
Challenge 2014 (\doiBPICfourteen; \citealp{vandongen2014bpic}), BPI Challenge
2013 incidents (\doiBPICthirteen; \citealp{steeman2013bpic}), and
\citet{steeman2013closed}, \citet{vandongen2015bpic}, \citet{vandongen2017bpic},
\citet{vandongen2019bpic}, \citet{polato2017helpdesk},
\citet{deleoni2015roadfines}, \citet{mannhardt2016sepsis} and
\citet{amaral2018incident}; the SHA-256 checksum of every downloaded file is
listed in \checksumfile. \nCorpusDownloaded\ files are downloaded and checksummed in
all, one log shipping as three; the pre-specified role-assignment rules of
Section~\ref{sec:design} admit \nLogs\ logs, yielding the \nPairs\
log--target pairs analysed here. Table~\ref{tab:corpus} accounts for every
other downloaded log, either by the exclusion code the rules gave it or by
the code \textsf{HELD\_OUT}, which marks a log reserved for a separate
pre-specified prediction and never offered to the admission rules
(\nHeldOutLogs\ of the checksummed files). Every analysis result is in the
release named in the code-availability statement, and one command
regenerates every result from the public logs; where later code would
print a summary differently, the correction register
(Supplement~\ref{app:corrections}) says so.
