
Every number in the manuscript is a macro, defined in the generated file
\texttt{paper/numbers.tex} that \texttt{scripts/make\_numbers.py} writes
from \texttt{results/*.csv}. The manuscript contains no numeric literal
outside that file and the generated tables. A number therefore cannot disagree
between the abstract, a table and the conclusion: there is one of it.

That removes one class of defect and creates another --- a wrong generator
makes the whole manuscript wrong \emph{consistently}, and nothing looks odd
--- so the architecture comes with seven controls.

\begin{description}
\item[The generator.] \texttt{make\_numbers.py} emits a visible
\textbf{??} for any macro whose source file is absent, and
\texttt{-{}-strict} exits non-zero if one remains. A partial build is
therefore visibly partial and cannot silently drop a claim.

\item[The verifier.] \texttt{scripts/verify\_numbers.py} re-derives each
checked macro from the result file with code written against the
\emph{definition} rather than against the generator, and compares. It also
enforces \nConditions\ consistency conditions that no single macro expresses
--- relations that must hold between numbers even when each is individually
correct. Among them: that every register-quality mechanism passed its
executed train-only check; that no surface is labelled uniformly beneficial
while carrying an unresolved cell, nor conditionally harmful while carrying a
beneficial one; that every region label is one of the six the manuscript
defines and that the labels partition the pairs; that the disjoint
functional-ANOVA components sum to one on every decomposition; that no
planned contrast reports a $p$-value the draw count cannot produce, and that
its Holm adjustment reproduces from the raw values; that no rank-based
metric's reduction moves under a monotone recalibration; that the cells a
region label ranges over are exactly the cells the simultaneous family that
licenses it controls; that the case study's split partitions its cohort; and
that the adjudicated set of the literature pilot is exactly the screened-in
set.

\item[The corruption suite.] \texttt{scripts/s13\_attack\_numbers.py}
corrupts one thing at a time --- a value in a result file, a value in
\texttt{numbers.tex}, a deleted macro, a train-only check flipped, a region
label made inconsistent with its counts, an adjudication file made
inconsistent with the coding file --- and requires the verifier to notice.
Every corruption is applied to a copy in a temporary directory, and the suite
refuses to start while an interrupted run's lock remains, so a corrupted file
cannot reach the working tree. A corruption of a \emph{result} file is
checked by regenerating the macros from the corrupted copy and then
verifying; without the regeneration, a quantity the verifier re-derives from
a different file than the generator reads would be untouched and the
corruption would pass.

\item[The condition on the set, not on the number.] Two macros, each
consistent with its own source, can still be called by the same name in the
prose while holding different values. The verifier therefore carries an
\textsc{estimands} table: one entry per quantity a reader would name in one
phrase, listing the macros that may hold it. Two members of an entry that
disagree is a failure; a quantity that legitimately takes two values under two
specifications gets two entries with different names, which the manuscript
must then use. Corruption \textsf{G1} tests it: it moves a value in one
result file and lets both the generator and the verifier read the moved
value, so that only the condition on the set can fail.

\item[The provenance record.] \texttt{results/provenance.json} holds the
SHA-256 of every analysis script at the moment its outputs were last accepted,
with a note saying why, and \texttt{make\_numbers.py -{}-strict} refuses to
certify a manuscript whose numbers come from a script that has changed since.
A missing file is loud and a stale one is silent; modification time cannot
tell them apart, because changing a script's output format does not make its
numbers wrong, so acceptance is a deliberate act with a recorded reason.

\item[The compliance linter.] \texttt{scripts/texlint.py} carries
\nLintChecks\ checks, among them: the abstract length, the keyword count, the
highlight lengths, the presence of the required statements, the absence of
any numeric literal in the prose, that every \texttt{\textbackslash input}
target exists, that a spelled-out count matches the list it introduces, and
signatures of typesetting defects that print as garbage without producing a
wrong number, such as a stray control character or a control word broken by
an escaped backslash.

\item[The claim registry.] \texttt{scripts/claim\_registry.py} writes one row
per macro: its value, every manuscript location that uses it, the generator
file and line that defined it, the result file that line reads, and whether
the verifier re-derives it independently. Because the manuscript contains no
numeric literals, the registry is exhaustive by construction, and
\texttt{-{}-check} fails a build in which a macro the manuscript uses is
unresolved. Its summary row counts the independently re-derived macros,
separately for the headline ones; the count is a property of a build and is
left in the file rather than quoted here.
\end{description}

\paragraph{What the harness does not do}
It guards numbers thoroughly and prose only where a guard was written by hand.
The generated-macro discipline makes one kind of inconsistency structurally
impossible --- the same quantity printed differently in two places --- and
does nothing about a sentence in which every printed number is correct and
the relation asserted between them is not. Nor does it catch a quantity that
is computed correctly, printed correctly and consistent everywhere while its
\emph{definition} is not the one the estimator addresses: Class~G of the
register in Section~\ref{app:corrections}, found by the diagnostics of
Section~\ref{app:noisy} and not by any check described here.

\paragraph{The inference surface is smaller than the declared surface, and the
grid is not uniform across the corpus}
Every point estimate comes from the full declared space; every \emph{band}
comes from the inference surface, a median
\inferenceShareAdmissibleMedianPct\ of each pair's admissible surface. It
is a subset of the declared surface cell for
cell and the share of positive cells differs between them by a median
\repGapMedian, but a study with compute to spare should equate the two. The
same budget shows in two further places. Every corpus family is declared at
\nDrawsSurfaceMax\ draws (the case study's own curve family and its ladder
run at their own, smaller budgets, Section~\ref{sec:dcabands} and
Table~\ref{tab:tau}) and every corpus family is effective at
\nDrawsEffectiveMin: a replicate that leaves any cell of a family without
outcome variation is dropped from that family, and under the weighted scheme
no replicate is dropped on any family. The accounting is reported although
the gap it measures is empty, because a reader cannot tell an empty gap from
an omitted one. And the pipeline axis
carries four levels on the case study's log and two or three elsewhere, by a
rule declared on row count before the runs, so a sensitivity index computed on
one pair is not strictly comparable with one computed on another.
